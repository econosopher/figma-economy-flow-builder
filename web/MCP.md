# Economy Flow MCP

The hosted server uses the same document validator, layout and save transaction as the web editor. Its source is included under the repository's MIT license. Connect directly to Cloudflare; Netlify does not receive server credentials.

| Environment | Server URL |
| --- | --- |
| Staging | `https://economy-flow-staging.twig-transcripts-mcp.workers.dev/mcp` |
| Production | `https://economy-flow.twig-transcripts-mcp.workers.dev/mcp` |

Both hosted environments have separate active Supabase accounts and OAuth configuration. See `DELIVERY.md` for live verification and operational limits. Self-hosted endpoints return 503 until configured.

## Connect

Add the URL as a Streamable HTTP MCP server in your client. Complete Economy Flow sign-in and consent. Reading diagrams is required; editing is selected by default, and GitHub submissions are an optional separate permission. Revoke a connection at `/connections`. Revocation takes effect at the API and database even while an OAuth token remains unexpired.

For Codex, add this to its MCP configuration, then run `codex mcp login economy-flow`. See [OpenAI's MCP configuration documentation](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).

```toml
[mcp_servers.economy-flow]
url = "https://economy-flow.twig-transcripts-mcp.workers.dev/mcp"
enabled = true
tool_timeout_sec = 120
```

For a client that accepts MCP JSON configuration:

```json
{
  "mcpServers": {
    "economy-flow": {
      "url": "https://economy-flow.twig-transcripts-mcp.workers.dev/mcp"
    }
  }
}
```

Use the client's OAuth flow. Do not paste a Supabase service key, GitHub token, or provider key into MCP configuration. The resource metadata lives at `/.well-known/oauth-protected-resource`.

## Tools

| Tool | Input and result |
| --- | --- |
| `browse_diagrams` | `search`, `source` (`all`, `preset`, `community`), `sort` (`most_viewed`, `newest`, `name`), `offset`, `limit`. Returns ranked metadata and view availability. |
| `list_my_diagrams` | `offset`. Returns your documents and revisions, recently edited first. |
| `read_diagram` | `reference`: an account document ID, `preset:<id>`, or `publication:<id>`. Returns editable JSON and revision. |
| `read_repository_presets` | Optional `id`. Reads the manifest or a preset at GitHub's current main commit and returns its commit SHA. |
| `validate_diagram` | `document`: v2/v3 JSON. Returns migrated JSON, migration notices and approximate routing checks. No save. |
| `preview_changes` | `documentId`, `expectedRevision`, and either `edits` or `replacement`. Returns a draft and diff. No save. |
| `create_diagram` | `operationId`, optional `document` or `copyFrom`, optional `name` and `visibility`. Returns saved JSON, revision, visibility and editor URL. |
| `edit_diagram` | `operationId` and `change` containing the same fields as `preview_changes`. Saves the batch atomically. |
| `render_diagram` | v3 `document`. Returns SVG, a 2× PNG, routing issues and private download URLs. Previews expire after one hour. |
| `preview_preset_submission` | `operationId`, `document`, `file`, `title`, `attribution`. Returns the exact public files and diff. |
| `submit_preset` | The preview's `operationId`. Opens a public pull request and returns its URL. Never merges. |

Operation IDs are UUIDs generated by the caller. Reuse the same ID and exact input after an uncertain response. A changed request requires a new ID. Saved edit receipts survive retries, including after later edits. Revision conflicts return 409: read the current document and review a new edit; do not silently overwrite it.

Example edit after reading the document and reviewing `preview_changes`:

```json
{
  "operationId": "c177f02e-b53c-47ec-af89-c68ef1d3de90",
  "change": {
    "documentId": "my-economy",
    "expectedRevision": 4,
    "edits": [
      { "op": "put", "entity": "cards", "value": { "id": "play", "label": "Complete a mission", "sources": ["Coins", "Equipment"] } },
      { "op": "remove", "entity": "cards", "id": "old-action" }
    ]
  }
}
```

`put` creates or updates an item by stable ID in `cards`, `edges`, `stages` or `groups`. Resource arrays and notes are card fields. `remove` deletes an item; card deletion includes connected edges. Stage/group deletion requires moving or deleting its cards in the same batch. Stage array order determines left-to-right placement; use a full replacement to reorder stages/groups. `rename`, `settings` and `visibility` operations change those document fields. Replacement preserves document ID and saved visibility; use a visibility edit explicitly to change privacy.

New account diagrams default to public. Private source documents remain private when copied unless the caller explicitly chooses public. Unsaved previews do not publish. A public GitHub contribution requires a public document copy and a separate submission call. A website lock cannot retract JSON already submitted to GitHub.

The renderer loads only its fixed application page and bundled assets, measures Inter text, and uses the editor's SVG/PNG exporter. It cannot navigate to user-supplied URLs. Download URLs require the owner's bearer token and, for OAuth tokens, the originating client and current read permission. Expired artifacts are inaccessible immediately and removed by hourly cleanup. Save failures, routing issues and private preview contents are never turned into public gallery items automatically.

## Activate each environment

1. Create dedicated staging and production Supabase projects. Apply every migration in filename order. Configure `SUPABASE_URL` and `SUPABASE_ANON_KEY`; install `SUPABASE_SERVICE_ROLE_KEY` as a Worker secret. Keep service credentials out of Vite and Netlify.
2. Enable email sign-in with a production SMTP sender. Include both a sign-in link and the OTP token in the email template. Configure the Auth site URL and callbacks to the direct Worker origin, including `/oauth/consent`. Verify an actual email sign-in and two separate accounts.
3. Enable Supabase's OAuth 2.1 server and dynamic client registration. Set the authorization path to `/oauth/consent`. Use asymmetric signing keys and PKCE. The consent UI is included in this application.
4. Insert the environment's canonical MCP URL into `public.mcp_configuration(singleton,resource_url)`. Enable the Postgres Custom Access Token Hook `public.mcp_access_token_hook`. It adds the MCP resource audience only for approved client grants, while retaining Supabase's `authenticated` audience for RLS requests. Verify this audience in an actual issued access token without logging the token.
5. Install a random `VIEW_HASH_KEY` Worker secret in each environment. This HMAC key anonymizes the browser visitor ID before daily deduplication. Counts start at zero; no historical views are inferred.
6. Create the repository GitHub App using `ops/github-app-manifest.json` as the permission specification. Install it only on `econosopher/figma-economy-flow-builder`. Set `GITHUB_APP_ID` and `GITHUB_INSTALLATION_ID`; store `GITHUB_APP_PRIVATE_KEY` as a PKCS#8 PEM Worker secret. Convert GitHub's downloaded RSA key with `openssl pkcs8 -topk8 -nocrypt` through protected stdin/stdout if necessary. Keep the key in your credential manager, never source control. Use a separate test installation/repository fixture for integration tests; production paths are deliberately fixed in source.
7. Provision the configured Browser Run binding. Test rendering, authenticated downloads and expiry. The binding intercepts renderer requests and serves application assets internally; it does not browse external sites.
8. Set `MCP_ENABLED` to `true` only after OAuth discovery, consent, revocation, audience checks and account isolation pass. Verify read, preview, create and edit from an actual MCP client. Test a specifically approved public preset contribution with the GitHub App.

The app reads live grants on every MCP request and relevant operation. Restrictive RLS applies to OAuth tokens, including direct database API calls. OAuth identity scopes do not replace these grants. No general filesystem, shell, arbitrary GitHub path, main-branch write or merge tool is exposed.

## Browse counts and operations

`GET /api/catalog` accepts the same catalog arguments as `browse_diagrams`. It ranks the complete matching preset/community dataset before pagination. `POST /api/catalog/views` accepts `{itemId,visitorId}` after a diagram is opened in the visible browser. `itemId` is `preset:<id>` or `publication:<uuid>`; `visitorId` is a browser-generated UUID. The Worker hashes it with the UTC day and uses an atomic database deduplication transaction. Identifiable owner opens, MCP requests, thumbnails, list fetches, private items and moderated publications are excluded. Copies have independent IDs; edits retain counts.

Rate limiting bounds automated traffic but is not proof of a unique human. View counts mean deduplicated browser opens, not unique people. Raw IP addresses are used only as ephemeral rate-limit keys, not retained in analytics tables. Daily event rows are cleaned after two days; aggregate counts remain. If the backend fails, bundled browsing remains available with counts marked unavailable and alphabetic ordering.

Monitor `mcp_tool_failed`, `mcp_render_failed`, `catalog_unavailable` and existing `api_error` events, plus `ops/monitor.sql`. Enable and restore a real Supabase backup into an isolated target before account release, then run `ops/restore-check.sql`, compare document hashes and test two-account isolation. Database backups exclude Storage bytes: preserve persistent objects separately; MCP previews are disposable. Keep integrations disabled in the restore target.

Run `npm test`, `npm run build` and `npx wrangler deploy --dry-run --env staging`. Browser runners include `tests/browser/public-catalog.js` and the development-only `tests/browser/render-parity.html`. These tests do not require production credentials or submit real GitHub pull requests.
